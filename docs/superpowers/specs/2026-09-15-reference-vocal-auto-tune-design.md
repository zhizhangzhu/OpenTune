# 独立参考人声自动修音设计

## 目标

在 OpenTune 现有 `AUTO Ref` 结构上，支持用户导入一段原曲独立人声 stem，作为待修人声的音高参考，自动生成只作用于目标人声的修音结果。

第一版只支持同一首歌、相近速度和相近起点的两段独立人声。用户自行完成人声分离；OpenTune 不负责从完整混音中分离人声。

## 已确认的范围

- AI 只负责音高和旋律分析，不引入新的训练流程。
- 复用现有 FCPE、音符生成、`ReferenceAnalysisService`、`ReferenceAutoAlign`、`AutoTunePitchShifter` 和渲染缓存。
- 原有普通 `AUTO` 保持可用。
- 原有 `AUTO Ref` 保持可用，不替换原有 placement 参考流程。
- 新的参考 stem 作为时间轴中的普通音频 placement 导入和绑定。
- 第一版不做人声分离、不处理完全不同的演唱结构、不引入复杂歌词级 DTW。

## 用户流程

1. 导入待修人声 stem。
2. 导入原曲独立人声 stem。
3. 将两个 placement 放置在相同或相近起点。
4. 在待修人声 placement 上打开参考绑定菜单。
5. 选择原曲人声 placement 作为参考。
6. 等待目标和参考音频的 AI 分析完成。
7. 执行现有 `AUTO Ref`。
8. OpenTune 只修改待修人声，参考 placement 保持不变。

界面需要显示参考绑定对象和分析状态：未绑定、分析中、分析成功或分析失败。没有参考绑定时，现有 `AUTO` 行为不改变。

## 数据流与组件职责

### 音频输入

参考 stem 和目标 stem 都通过现有音频导入与 placement 系统进入工程。参考 placement 使用其原始音频数据，不需要额外的媒体复制机制。

### AI 分析

目标和参考音频分别通过现有 FCPE 推理流程提取 F0。分析任务继续由后台服务执行，避免阻塞消息线程或音频线程。

参考 F0 经过现有音符生成器转换为参考音符和时间特征，并写入参考特征缓存。目标 F0 和目标分析状态沿用现有内容分析状态。

模型加载、ONNX Runtime、DirectML 和 CPU 回退逻辑保持不变。模型缺失或推理初始化失败时，任务进入失败状态并保留原音频内容。

### 时间对齐

使用现有 placement 时间范围、`EffectiveTimeMap` 和 `ReferenceAutoAlign` 计算参考与目标的重叠区域。第一版只依赖同曲、相近速度和相近起点；不保证不同演唱结构之间的全局动态时间规整。

### 音高修正

- 只在目标和参考的有效重叠区域内生成修音目标。
- 参考存在明确音高时，目标音高向参考音高靠拢。
- 参考无声、低置信度或没有有效音符时，不生成强制修音目标。
- 目标的静音、呼吸、尾音和没有匹配参考的区域保持原样。
- 继续使用现有 `AutoTunePitchShifter`、声码器选择和 Stage 2 渲染流程。
- 没有产生实际变化时返回明确的 no-op 状态，不写入半成品。

## 兼容性要求

- 普通 `AUTO` 的入口、参数和输出行为不变。
- 原有 `AUTO Ref` 的 placement 绑定和分析流程不变。
- 新参考 stem 只是新增一种可绑定的 placement 来源。
- 参考分析失败不能污染目标内容状态，也不能覆盖原始音频。
- 现有工程状态保存与加载应继续兼容；新增状态字段必须提供默认值。

## 错误处理

需要明确反馈以下情况：

- 未选择参考片段；
- 参考片段与目标片段相同；
- 两个片段没有时间重叠；
- 参考或目标 AI 分析未完成或失败；
- FCPE 模型、ONNX Runtime 或运行时 DLL 缺失；
- DirectML 不可用且 CPU 回退也失败；
- 参考音频没有足够有效音高；
- 修音结果没有实际变化。

所有失败都应保持目标原始音频和工程状态可恢复，不生成不可用的渲染结果。

## 测试与验收

### 单元测试

- 参考绑定的有效性检查；
- 自引用、无重叠和无效时间范围；
- 参考特征未就绪、失败和空音符；
- 只修改目标内容的 mutation/commit 行为；
- no-op 结果不产生渲染提交；
- 普通 AUTO 和现有 AUTO Ref 回归测试。

### AI 冒烟测试

使用当前项目中的 `models/fcpe.onnx`，对两段实际人声输入执行 F0 提取，确认：

- 模型可以加载；
- CPU 或 DirectML 至少有一个推理后端可用；
- 返回非空 F0 轨迹；
- 无效或静音输入不会导致崩溃；
- 分析失败可被转换为用户可见的失败状态。

### 构建验收

- `OpenTune_Standalone` Release 构建成功；
- `OpenTune_VST3` Release 构建成功；
- 原有模型和运行库复制流程保持成功；
- 手动导入两段同曲独立人声后可以绑定参考、完成分析并执行修音。

## 非目标

- 完整混音自动人声分离；
- 新 AI 模型训练；
- 不同歌曲或完全不同段落之间的旋律迁移；
- 歌词识别；
- 第一版独立批处理命令行工具；
- 改写现有 FCPE、ONNX Runtime 或音频渲染核心。
